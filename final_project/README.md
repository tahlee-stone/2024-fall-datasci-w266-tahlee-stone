# README: Hallucination Detection in Financial Dialogue Systems for Retail Bank Customer Service Chatbots


This project fine-tunes a **cross-encoder classifier** to detect hallucinations in responses generated by large language models (LLMs). Specifically, it evaluates **groundedness**—the degree to which a model's generated response is faithful to a given context. Hallucination detection is a classification task based on **(query, context, response) triplets. 

This repository contains code and documentation for fine-tuning DeBERTa-v3 cross-encoder for the task of hallucination detection on a HaluBench hallucination benchmark dataset and a synthetically generated RetailBankQA dataset. 

Code is also provided to compare this model to two baselines: 1) a prompted GPT4 LLM evaluator; and 2) an off-the-shelf contextual grounding guardrail from AWS Bedrock. 

Set up for both of these models is detailed below.

## 📚 Dataset Sources

### HaluBench Benchmark

- \~15,000 (query, context, response) triplets annotated for hallucination detection
- Subsets used: DROP, FinanceBench, PubMedQA, RAGTruth
- Excludes HaluEval and COVID-QA due to length and label bias
- See for further detail:
  https://huggingface.co/datasets/PatronusAI/HaluBench
  https://arxiv.org/abs/2407.08488


### RetailBankQA Synthetic Dataset

- 2,770 synthetic examples based on Banking77 intents (https://huggingface.co/datasets/PolyAI/banking77)
- Contexts generated using `gpt-4o-mini`, grounded responses via `gpt-4o`, hallucinated responses via `gpt-3.5-turbo`
- Labels verified using OpenAI `o3-pro` model with 90% agreement

## ☁️ AWS Bedrock Setup

### 1. **AWS Account Creation & Permissions**

- Sign up at: [https://aws.amazon.com/](https://aws.amazon.com/)
- Navigate to IAM Console
  - Create an IAM user with programmatic access
  - Attach the following policies:
    - `AmazonBedrockFullAccess`
    - `AmazonAPIGatewayInvokeFullAccess`

### 2. **Access Key Configuration**

Create a `.env` or use shell variables:

```bash
export AWS_ACCESS_KEY_ID="your-access-key"
export AWS_SECRET_ACCESS_KEY="your-secret-key"
export AWS_REGION="us-east-1"
```

### 3. **Enable Guardrails**

- Navigate to Bedrock console > Guardrails
- Create a contextual grounding guardrail
  - Enable *Contextual Grounding*
  - Disable *Relevance checks*
  - Set *Threshold* to `0.5`
- Use the `apply_guardrail()` API endpoint in scripts with Claude Sonnet 4 as the model

## 🧠 Key Technical Details

- **Model**: DeBERTa-v3-base cross-encoder with added classification head
- **Input Format**: `[CLS] query [SEP] context [SEP] response [SEP]`
- **Loss**: Binary cross-entropy
- **Chunking Strategy**: Overlapping windowing for inputs >512 tokens
- **Metrics**: Accuracy, Macro Precision/Recall/F1
- **Baselines**:
  - GPT-4o zero-shot with structured JSON prompt (Jinja2)
  - AWS Bedrock contextual grounding API

---

## 📌 Notes

- The model is designed for deterministic outputs and reproducible audits
- GPT-based baselines offer richer reasoning but suffer latency and cost trade-offs.
- AWS Bedrock guardrails are useful but opaque and inflexible.
